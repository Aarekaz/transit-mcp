# Metro MCP Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one secure, adaptive Transit Board MCP App to all thirteen Metro MCP transit tools without changing their existing wire contracts for non-Apps clients.

**Architecture:** The Worker continues to register the existing MCP 2026-07-28 tools directly with `@modelcontextprotocol/server` v2. Each tool receives the same stable Apps `_meta.ui` reference, the server advertises `io.modelcontextprotocol/ui`, and one authenticated `ui://metro-mcp/transit-board.html` resource serves a committed single-file Vite bundle from the existing `ASSETS` binding. The browser bundle uses the official Apps SDK only inside the iframe, narrows tool results at runtime, dispatches to thirteen purpose-built views, and can refresh only its originating allowlisted tool with unchanged arguments.

**Tech Stack:** Bun 1.3.x, TypeScript, MCP server 2.0.0, MCP SDK 1.30.0, MCP Apps SDK 1.7.5, Vite 8.2.1, vite-plugin-singlefile 2.3.3, Vitest 4.1.10, happy-dom 20.11.6, Playwright Test 1.62.1, Cloudflare Workers/Workerd.

**Spec:** `docs/superpowers/specs/2026-08-19-mcp-apps-design.md`
