Connect an MCP client

The production MCP endpoint is anonymous Streamable HTTP. No login is required. No client credentials, token, or OAuth flow is required; stale Authorization headers are ignored.

Claude Desktop / Cursor config 
{
  "mcpServers": {
    "metro-mcp": {
      "url": "https://metro-mcp.anuragd.me/mcp"
    }
  }
}

Codex CLI

Add the same anonymous Streamable HTTP endpoint from a terminal.

codex mcp add metro-mcp https://metro-mcp.anuragd.me/mcp

Generic client

Use name metro-mcp, URL https://metro-mcp.anuragd.me/mcp, and transport streamable-http.

MCP tools

Every tool is read-only and returns structured content plus serialized JSON text for older clients. Station-name tools search first, and ambiguous matches can trigger MCP elicitation where the client supports it.

Station discovery

search_stations, get_all_stations, and get_stations_by_line cover both DC and NYC. Results include IDs, names, lines, coordinates, and addresses when available.

Arrivals

get_station_predictions resolves a station name or code and returns line, destination, minutes away, arrival time, status, cars, direction, and track where the feed provides it.

Service state

get_incidents works for DC and NYC. get_elevator_incidents is DC-only and returns unit, station, symptom, outage time, estimated return, and update time.

DC bus and rail operations

get_bus_predictions, get_bus_routes, get_bus_stops, get_bus_positions, and get_train_positions expose WMATA bus arrivals, route catalogs, stop search, live buses, and live train positions.

NYC route detail

get_route_info returns route names and service descriptions. get_station_transfers returns platform and nearby transfers with walk times in seconds and minutes.

Progress and safety hints

get_all_stations emits progress notifications when clients pass a progress token. Tool annotations mark calls as read-only, idempotent, and open-world because they query live transit systems.

Data sources and cache windows

metro-mcp normalizes official agency data into MCP-friendly JSON. DC data is fetched from WMATA REST APIs with Cloudflare edge caching; NYC uses MTA GTFS-realtime feeds plus bundled station and route metadata.

Resources and prompts

Clients that support more of MCP can read resource URIs directly and invoke prompt templates instead of hand-writing tool instructions.

TypeNameWhat it does
Resourcetransit://stations/{city}/{id}Station metadata with coordinates, lines, address, and transfer records.

Cloudflare stack

metro-mcp runs as a small Cloudflare application: the edge handles web pages, anonymous MCP requests, lightweight rate limiting, and logs close to the user.

Workers

The Worker is the front door. It serves the site, accepts anonymous MCP traffic, and routes requests to the right part of the app.

Durable Objects

Durable Objects keep each MCP session stateful. They let clients resume conversations, receive streamed events, and stay connected without keeping every session hot all the time.

KV

Cloudflare rate-limit bindings protect shared public traffic at each edge location and source IP.

Assets and logs

Cloudflare serves the landing page and docs as static assets, while Worker logs and source maps make production behavior easier to debug after deploys.
